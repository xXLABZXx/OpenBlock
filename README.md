# OpenBlox

> **Working title.** A clean-room, Roblox-compatible game engine and emulator —
> not affiliated with, endorsed by, or connected to Roblox Corporation.

OpenBlox aims for maximum compatibility with existing Roblox experiences:
real Luau script execution, a reflection-driven `Instance`/`DataModel` core,
and modular physics, rendering, networking, audio, and platform services.

**Legal stance:** clean-room implementation only — public Creator
documentation, MIT-licensed Luau, and permissively licensed dependencies.
No Roblox source code, no proprietary Roblox assets, no bypassing of Roblox
authentication, security protections, access controls, or restrictions.
See `docs/ARCHITECTURE.md` §1–2.

## Quick start (v0.1 prototype, headless)

Requirements: CMake 3.16+, a C++17 compiler, git, internet access (fetches
Luau 0.742 via `FetchContent` on first configure).

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/openblox scripts/demo.luau
./build/openblox_tests   # runs the compatibility suite
```

The test run regenerates `docs/COMPATIBILITY.md` — the honest, machine-checked
record of what works, partially works, or is unsupported.

## Layout

```
openblox/
  docs/          ARCHITECTURE.md, ROADMAP.md, COMPATIBILITY.md (generated)
  src/           C++ engine: luau-runtime, core-datamodel, datatypes,
                 scripting, and module interfaces (physics/rendering/…)
  scripts/       demo experience scripts
  tests/         compatibility test suite (Luau)
  third_party/   FetchContent-populated (Luau); never vendor proprietary code
```

## Current status

Phase 1 (v0.1): headless core — real Luau VM, `Instance`/`DataModel`,
datatypes, signals, `task` scheduler, script contexts, demo + tests.
Rendering, physics, networking, and audio are architected module interfaces;
backends land in v0.3–v0.5 per the roadmap.
